# Безопасность

## Ключи и .env

- **Файл `.env` в `.gitignore`** — ключи не должны попадать в репозиторий.
- Используется шаблон **`.env.example`**: скопируй в `.env` и подставь свои значения.
- В коде ключи берутся только из `dotenv` (`lib/main.dart`), в репозитории **нет захардкоженных** SUPABASE_URL / SUPABASE_ANON_KEY (кроме тестовых плейсхолдеров в `test/`).

Если ключи когда-либо попадали в историю git:
1. Смени **anon key** (и при необходимости service role) в Supabase: Dashboard → Settings → API.
2. Удали секреты из истории (например, `git filter-repo` или BFG Repo-Cleaner) и force-push (осторожно в общих ветках).

## RLS (Row Level Security) в Supabase

Anon key работает только в рамках политик RLS. Все таблицы с пользовательскими данными защищены RLS (`supabase/schema.sql`).

### Кто что может делать (через anon key после входа)

| Таблица | SELECT | INSERT | UPDATE | DELETE |
|--------|--------|--------|--------|--------|
| **users** | все | только свой профиль (`id = auth.uid()`) | только свой | — |
| **products** | все | только от своего `seller_id` | только свои | только свои |
| **product_likes** | все | только свой `user_id` | — | только свои |
| **product_comments** | все | только свой `user_id` | — | только свои |
| **posts** | все | только свой `user_id` | только свои | только свои |
| **post_likes / post_dislikes / reposts** | все | только свой `user_id` | — | только свои |
| **post_comments** | все | только свой `user_id` | — | только свои |
| **followers** | все | только свой `follower_id` | — | только свои |
| **stories** | все | только свой `user_id` | только свои | только свои |
| **story_replies** | все | только свой `user_id` | — | только свои |
| **notifications** | только свои (`user_id = auth.uid()`) | нет (создаются триггерами/бэкендом) | только свои | — |
| **favorites** | только свои | только свои | — | только свои |
| **orders** | только свои | только свои (`buyer_id`) | только свои | только свои |
| **categories** | все (только чтение) | — | — | — |

Итог: **anon key не даёт лишних прав** — запись только от имени текущего пользователя, чтение публичных данных для ленты/профилей, приватные сущности (уведомления, избранное, заказы) — только свои.

## Storage

Политики в `schema.sql`: загрузка в бакеты `products`, `posts`, `stories` разрешена только **authenticated** пользователям; при необходимости ограничь чтение по папкам (например, по `user_id`).
