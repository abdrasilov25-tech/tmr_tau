# tmr_tau — как работает приложение и что добавить

## Как работает приложение

### Концепция
**tmr_tau** — гибрид маркетплейса и соцсети в духе Instagram/TikTok: пользователи публикуют товары, листают общую ленту, лайкают, комментируют и подписываются на продавцов.

### Технологии
- **Flutter** + **flutter_bloc** (состояние), **go_router** (навигация)
- **Supabase**: Auth, БД (PostgreSQL), Storage (фото товаров и сторис)
- **Clean Architecture**, разбивка по фичам: auth, feed, product, profile, stories, comments, notifications

### Поток пользователя

1. **Старт** → Splash → при наличии сессии переход на ленту, иначе на логин/регистрацию.
2. **Авторизация** — вход и регистрация через Supabase Auth; после входа создаётся запись в `public.users` (профиль).
3. **Главная (лента)** — вертикальный скролл карточек товаров:
   - сверху полоса сторис (пока заглушка: «Ваша история», «Сделка дня» и т.д.),
   - карточка: фото, продавец (аватар + имя), кнопки лайк / комментарий, подписаться, название, цена.
4. **Поиск** — поле ввода, поиск по товарам; при пустом запросе показывается блок «В тренде» (по лайкам).
5. **Добавить товар** — выбор фото, название, цена, описание, категория → загрузка в Storage и запись в `products`.
6. **Уведомления** — список уведомлений из таблицы `notifications`, кнопка «Прочитать все».
7. **Профиль** — свой профиль: аватар, имя, био, пункты «Мои заказы», «Избранное», «Мой магазин», «Добавить товар», «Выйти». Чужой профиль (продавца): аватар, имя, био, счётчики подписчиков/подписок/товаров, кнопка «Подписаться»/«Отписаться», сетка товаров.

### Нижняя навигация (5 вкладок)
| Вкладка       | Маршрут           | Содержимое                          |
|---------------|-------------------|-------------------------------------|
| Главная       | `/home/feed`      | Лента товаров + сторис             |
| Поиск         | `/home/search`    | Поиск + тренды                      |
| Добавить      | `/home/add`       | Форма добавления товара             |
| Уведомления   | `/home/notifications` | Список уведомлений              |
| Профиль       | `/home/profile`   | Свой профиль                        |

### Данные (Supabase)

- **users** — профили (имя, аватар, био, счётчики подписчиков/подписок).
- **products** — товары (название, описание, цена, фото, категория, продавец, счётчики лайков/комментариев).
- **product_likes**, **product_comments** — лайки и комментарии к товарам.
- **followers** — кто на кого подписан (follower_id → following_id).
- **stories** — сторис (фото/видео, срок жизни 24 ч).
- **notifications** — уведомления (тип, заголовок, текст, ссылка на товар, прочитано/нет).
- **favorites**, **orders** — избранное и заказы (частично используются в UI).

## Что нужно добавить / доработать

### 1. Комментарии к товару (UI)
- **Сейчас:** есть домен и репозиторий (`CommentsRepository`, `ProductCommentEntity`), нет экрана.
- **Добавить:** на экране карточки товара (ProductDetailPage) — кнопка «Комментарии», по нажатию bottom sheet или отдельная страница со списком комментариев (аватар, имя, текст, дата) и полем «Добавить комментарий» с вызовом `CommentsRepository.addComment`.

### 2. Сторис (полный цикл)
- **Сейчас:** таблица `stories`, репозиторий (добавление, получение активных, по пользователю). На ленте — только заглушка (кружки без реальных данных).
- **Добавить:**
  - загрузка сторис: экран/модалка выбора фото (и при желании видео) → загрузка в Storage (bucket `stories`) → `StoriesRepository.addStory`.
  - отображение: полоса сверху ленты — реальные сторис по `getActiveStories()` (сгруппировать по пользователю), тап — полноэкранный просмотр (свайп между сторис, таймер 24 ч).
  - удаление просроченных: cron или Edge Function в Supabase, раз в час удалять `stories` где `expires_at < now()`.

### 3. Уведомления (создание событий)
- **Сейчас:** экран списка и пометка «прочитано» есть; записи в `notifications` нигде не создаются.
- **Добавить:** при действиях пользователей писать в `notifications`:
  - лайк товара → у владельца товара: «Кто-то лайкнул ваш товар»;
  - комментарий → владельцу товара;
  - подписка → тому, на кого подписались.
  Реализация: в репозиториях/блоках после лайка/комментария/подписки вызывать вставку в `notifications` (или общая функция/сервис «создать уведомление»).

### 4. Редактирование профиля
- **Сейчас:** в своём профиле отображаются имя, аватар, био из `users`, но редактировать их нельзя.
- **Добавить:** пункт «Редактировать профиль» → экран/модалка: смена аватара (выбор фото → Storage → URL в `users.avatar`), поля имя и био, кнопка «Сохранить» → `ProfileRepository.updateProfile`.

### 5. Избранное (интеграция с лентой/карточкой)
- **Сейчас:** таблица `favorites` и пункт «Избранное» в профиле; страница FavoritesPage есть, но не в нижней навигации.
- **Добавить:** на карточке товара (и в ленте) кнопка «В избранное» (иконка закладки), переключение через репозиторий избранного; на странице «Избранное» — список избранных товаров из БД.

### 6. Заказы и корзина
- **Сейчас:** есть страницы корзины и заказов, таблицы `orders` (и при необходимости корзина в БД или локально).
- **Добавить:** в карточке товара кнопка «В корзину» / «Купить»; полный поток: корзина → оформление заказа → запись в `orders`, уведомление продавцу (через `notifications`).

### 7. Поиск по продавцам
- **Сейчас:** поиск только по товарам (название, описание).
- **Добавить:** в том же экране поиска вкладка или фильтр «Продавцы» и запрос к `users` по имени (или отдельный endpoint), список карточек продавцов с переходом в профиль.

### 8. Мелочи и устойчивость
- **Схема БД:** убедиться, что в Supabase применён актуальный `supabase/schema.sql` (в т.ч. `products.likes_count`, `comments_count`, `category`), и созданы бакеты Storage `products`, `stories`.
- **Ошибки:** обработать типичные ошибки Supabase (сеть, RLS, дубли) и показывать пользователю понятные сообщения.
- **Pull-to-refresh** на ленте и на экране уведомлений.
- **Загрузка аватара** при регистрации/редактировании профиля (опционально).
